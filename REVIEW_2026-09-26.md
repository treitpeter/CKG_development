# Development branch repair — 26 September 2026

Reviewed the development branch before its September 2026 portability repairs.

## Reproducible setup and startup defects

- Bundled data/log paths referred to another checkout on one HPC filesystem.
  Relative defaults now resolve against the package checkout, with `CKG_ROOT`
  and `CKG_CONFIG_FILE` overrides. Absolute deployment paths remain supported.
- Dependency installation was hidden in legacy setuptools command hooks and
  omitted unconditional imports. Dependencies now appear in package metadata;
  editable installation, sdist and wheel builds use the standard build backend.
- Reinstalling reset the connector password, while fresh Neo4j installations
  never received that password. Existing credentials are preserved; the initial
  password is set only for a newly downloaded database.
- Status stopped at the first unavailable service. Startup could announce
  success without a working web app, and global process matching could stop
  another checkout. Status now covers all services; startup checks connectivity
  and HTTP; shutdown targets this checkout and cleans up its Celery workers.
- Four download endpoints used removed Flask arguments. Regression tests
  exercise actual HTTP downloads through the Flask test client.
- Functional smoke-test exceptions did not affect the exit status. They now do.

## Validation

Clean Python 3.12 environment, installed with `pip install -e '.[test]'`:

- `python -m pip check`: no broken requirements.
- `python -m pytest -q`: offline configuration, connector, launcher, download,
  homepage and worker-lifecycle regression tests.
- `python test_ckg.py`: all 55 module imports and five library checks passed.
- `python -m build`: sdist and wheel built successfully.
- `bash -n install.sh start.sh` and `git diff --check` passed.

GitHub Actions repeats installation, tests, smoke checks and builds on Python
3.10 and 3.12. The 20 historical external-download checks are explicitly
opt-in (`pytest --run-network`); they have not been revalidated in this review.

This review did not load a knowledge graph, run production services, benchmark
scientific analyses, validate optional R/WGCNA integrations, or modernize all
legacy Docker/HPC scripts. Import success is not evidence of analytical accuracy.
Service orchestration has regression coverage for stopped/missing services and
ownership/cleanup logic; a complete deployment still needs a service-level test.

## Public source cleanup

Removed deployment-specific scheduler scripts, local demonstration scripts, and
obsolete container recipes. Cleared saved notebook outputs/execution metadata,
replaced machine-specific paths with portable examples, removed environment
export prefixes, and removed the bundled database password and automatic email
destinations. Author attribution and upstream licenses remain intact. Regression
checks reject machine paths, recognizable private keys and saved notebook outputs.
These checks reduce accidental disclosure; they are not a proof that arbitrary
content contains no sensitive information. Historical source was subsequently
sanitized with maintainer approval; see [HISTORY_CLEANUP.md](HISTORY_CLEANUP.md).
